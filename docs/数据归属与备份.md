## 二、数据归属图（谁拥有什么）

| 数据 | 存储 | 权威 | 备注 |
|---|---|---|---|
| 会员账号/密码/邮箱 | PG `user` 表 | Next.js 业务层 | 唯一账号体系，网关只读 |
| 余额/积分流水 | PG `credit_grant` / `credit_ledger` | credits.ts（事务+行锁） | **只增不改**，requestId 幂等 |
| 充值订单 | PG `pay_order` | 支付回调幂等（providerEventId 唯一） | 补单必须单事务 |
| API Key | PG `user_api_key`（sha256 哈希） | apikey.ts | 明文只在创建时返回一次 |
| 模型/厂商/Key/定价 | PG `ai_vendor` / `vendor_api_key` / `ai_model` 等 | 后台模型库 | 上游 Key 密文（STORAGE_KEY_SECRET AES-GCM） |
| 网关请求/用量 | PG `usage_record` | gateway/usage.ts | 每请求记录含价格快照语义 |
| 计费对账 | PG `billing_reconcile` | billing-reconcile.ts | settle/refund 失败兜底，60s 重试 |
| 邮件验证码/模板 | PG `email_code` / `email_template` | mailer.ts | 验证码只存哈希 |
| 站点配置 | PG `site_setting`（key-value JSON） | settings.ts（30s 缓存） | 含 email 配置（SMTP 密码密文） |
| 搜索索引 | MeiliSearch（Docker 127.0.0.1:7700） | **派生数据** | 可全量重建（scripts/reindex-meili.mjs），不备份 |
| 限流/验证码冷却 | 进程内存 Map | **瞬态** | 多实例前迁 Redis（看板 #7） |
| 上传文件/生成资产 | public/uploads + S3 桶（generated_asset 登记） | 文件系统/桶 | uploads 不进部署包；生成资产 30 天过期清理 |

**规则**：Redis/内存永远是缓存与瞬态，账本事实只在 PostgreSQL；Meili 删库可重建；任何资金修正走冲正流水，禁止 UPDATE 历史。

## 三、备份与恢复

| 对象 | 方式 | 频率 | 恢复演练 |
|---|---|---|---|
| PostgreSQL | 服务器内 `pg_dump -Fc`（Docker 容器 postgresql_18_kpjt，35432→5432）落盘 + 下载到本地留存 | 手动（每次大版本前）+ 建议加 cron 每日 | 用 `pg_restore --no-owner --dbname=...` 恢复到隔离库验证 |
| .env | 服务器 600 权限，**密钥不入 Git**；本地 `.ssh/` 与密钥另有保管 | 变更时 | JWT_SECRET 丢失 = 全站登录态失效（可接受重新登录） |
| S3 桶密钥 | SiteSetting 内密文 + STORAGE_KEY_SECRET | 随 PG 备份 | STORAGE_KEY_SECRET 丢失 = vendor key/SMTP 密码不可解密，需全部重录 |
| MeiliSearch | 不备份（可由 PG 全量重建） | — | `node scripts/reindex-meili.mjs` |
| 代码 | Git（用户自行提交）+ 本地工作区为源头 | 每次 push | 服务器源码 = 部署包同步，不做独立权威 |

### 恢复优先级（灾难场景）

1. PG 恢复 → 2. pm2 起服务（.env 在位）→ 3. Meili 全量重建 → 4. 验证登录/充值/网关计费各一笔 → 5. CDN/Nginx 检查
